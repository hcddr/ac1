Das Original ZEAP 2.0 für den NAS-Computer ist extrem kompakt: der ganze Assembler belegt nur 4K!

Der Quellcode wird komprimiert abgelegt.
Assembliert wird Zeile für Zeile im Bildwiederholspeicher.
2 Pässe: 1. Aufbau der Sybmoltabelle, 2. Assemblieren mit ggf. Listen und ggf. Codeerzeugung
jedesmal wird der Quellcode auf den Bildschirm entpackt und von dort geparst

Der Assemblerkern wurde unverändert in den EDAS übernommen. 
Das Arbeiten im Bildwiederholspeicher wurde beibehalten; allerdings ist beim AC1
der Bildwiederholspeicher genau andersherum aufgebaut (links oben = letzte Adr.)
Daher mussten die Routinen modifiziert werden, die den Bildwiederholspeicher nutzen (Unpack, Parse, ...)

Der EDAS verwendet eine weitergehene Komprimierung des Quellcodes: Leerzeichen werden zusammengefasst.

Der Assemblerkern enthält keine Tabelle der OP-Codes, stattdessen werden Parse-Bäume genutzt.
Das spart Speicherplatz, ist aber langsamer als eine einfache Liste.
Im Mnemonics-Parsebaum ist auch der komplette OP-Maschinencode integriert.

Ein Scanner zerlegt die Quellzeile in Token. Register und Adressen etc. werden zu Token.

Einstieg in den Parser mit dem ersten Token (Tiefe 1). Wenn es gefunden wird, wird mit dem nächsten Token
ab dieser Position im Baum weitergesucht mit Tiefe 2 usw; bis der Code komplett gefunden wurde (eine Zweigspitze 
im Baum erreicht wurde).
z.B. POP rr -> 4 Token: Tiefe 1 "P", Tiefe 2 "O", dann Test auf "P", Test auf Token "rr" -> gefunden

weiter gibt es einen Parsebaum für benannte Parameter (Registernamen, Flagnamen, $)

es gibt einen Ausdrucksevaluator, der Symbole auswertet und einfache Ausdrücke berechnet

es gibt 2 spezielle NAS-Befehle
RCAL ofs	-> rst 10h n
SCAL code	-> rst 18h n
